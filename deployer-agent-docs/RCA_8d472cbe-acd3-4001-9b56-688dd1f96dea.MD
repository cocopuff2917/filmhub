# RCA — filmhub-918 redeploy failed (run 8d472cbe-acd3-4001-9b56-688dd1f96dea)

## Symptom
Deploy failed at the `deploy_k8s` step: "deployment failed to become ready: timeout waiting for deployment to be ready". nginx logged `connect() failed (111: Connection refused)` to `127.0.0.1:8001/health` and then `Backend died, shutting down nginx...`. The rollout never became ready, so the health check never passed and the run was never promoted.

## Root cause (SOURCE-level — missing Python dependency)
The FastAPI backend crashes on boot with:
```
ModuleNotFoundError: No module named 'pillow_avif'
  File "/app/backend/server.py", line 32, in <module>
    from pillow_avif import AvifImagePlugin
```
`backend/server.py:32` imports `from pillow_avif import AvifImagePlugin`, but `backend/requirements.txt` does NOT list the package that provides the `pillow_avif` module. The file currently pins `pillow==12.3.0` (line 73) but has no `pillow-avif-plugin`. uvicorn fails to import the app, the backend process dies, nginx has no upstream → health check fails → k8s rollout times out.

This is not a manifest/infra fault. The previous successful run (8b1dd013, still live and serving) predates the `pillow_avif` import being added to the source.

## Verification (reproduced + fixed in eph sandbox)
- Confirmed `backend/server.py:32` imports `from pillow_avif import AvifImagePlugin`.
- Confirmed `backend/requirements.txt` contains `pillow==12.3.0` but no `pillow-avif-plugin`.
- Reproduced: `python3 -c 'import pillow_avif'` → `ModuleNotFoundError: No module named 'pillow_avif'`.
- Fix verified: after `pip install pillow==12.3.0 pillow-avif-plugin`, the exact import chain from server.py (`from PIL import Image, ImageOps; from pillow_avif import AvifImagePlugin`) succeeds → `IMPORT CHAIN OK`.

## Fix (to apply in source — E1)
Add the missing dependency to `backend/requirements.txt`, e.g.:
```
pillow-avif-plugin==1.5.2
```
(Add a pinned `pillow-avif-plugin` line alongside the existing `pillow==12.3.0`.) Then re-trigger the deploy. The build will reinstall requirements and the backend will boot.

## Note
Current live app (run 8b1dd013) is unaffected — the failed run was never promoted. Only the new redeploy is blocked until the dependency is added.
