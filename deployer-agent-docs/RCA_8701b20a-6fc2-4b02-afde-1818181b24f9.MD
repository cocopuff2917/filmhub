# RCA — filmhub-918 redeploy failure (run 8701b20a-6fc2-4b02-afde-1818181b24f9)

## Summary
The redeploy failed at the `deploy_k8s` step with `deployment failed to become ready: timed out waiting for the condition`. That timeout is a **symptom**, not the cause. The real cause is a **backend boot crash**: a missing Python dependency makes uvicorn exit immediately, so the pod never passes its health check.

## Root cause
`backend/server.py` line 32 imports:
```python
from pillow_avif import AvifImagePlugin
```
The `pillow_avif` module is provided by the PyPI package **`pillow-avif-plugin`**, which is **NOT listed in `backend/requirements.txt`**. The file only contains `pillow==12.3.0` (line 73). At container start the backend dies:
```
ModuleNotFoundError: No module named 'pillow_avif'
  File "/app/backend/server.py", line 32, in <module>
    from pillow_avif import AvifImagePlugin
Backend died, shutting down nginx...
nginx: connect() failed (111: Connection refused) ... GET /health -> 127.0.0.1:8001
```
Nginx then has no upstream, `/health` returns connection-refused, and the K8s rollout times out.

Note: the build step succeeds (the image builds fine) because the import is only exercised at runtime. This is why it surfaces as a deploy/health-check timeout rather than a build error.

## Verification (reproduced in eph sandbox on this run's source)
- `python3 -c 'from pillow_avif import AvifImagePlugin'` → `ModuleNotFoundError: No module named 'pillow_avif'` (reproduced the exact failure).
- `pip install pillow-avif-plugin` → installs `pillow-avif-plugin-1.6.0`.
- After installing it alongside `pillow==12.3.0`: `from PIL import Image, ImageOps; from pillow_avif import AvifImagePlugin` → **FULL import OK**.

## Fix (E1 to apply in the source environment)
Add the missing dependency to **`backend/requirements.txt`**:
```
pillow-avif-plugin==1.6.0
```
(Pinned to the verified version; it depends on Pillow, which is already present as `pillow==12.3.0`, so this satisfies the build even though the Dockerfile installs with `--no-dependencies`.)

Then redeploy. No manifest changes are required.

## Why the deployer agent did not auto-fix + redeploy
This is an application-source dependency fix (edit to `backend/requirements.txt`), which is owned by the main agent (E1). The deployer agent only applies deployment-manifest fixes. After E1 adds the dependency, re-trigger the deploy.
